# 待办事项记录（新增待办）设计

## 1. 需求与范围

### 1.1 背景与目标

内部用户需要随手记录日常待办事项、避免遗漏。本期实现最小闭环：用户通过命令行提交「事项名称 + 描述」，系统校验后可靠地保存为一条待办记录，并返回该待办的唯一标识。

### 1.2 核心功能

- 新增待办事项：事项名称（必填）＋ 描述（选填），校验后持久化到本地 JSON 文件并返回待办 id。

### 1.3 约束与非功能要求

- 仅使用 Go 标准库，不引入外部依赖。
- 持久化：本地 JSON 文件。
- 单用户、单文件、无并发写场景。

### 1.4 排除范围

- 不做待办的查询 / 编辑 / 删除 / 完成（属后续需求）。
- 不做数据库、网络服务或 HTTP 接口。
- 不做多用户与认证授权。

## 2. 总体架构

单一 Go 命令行程序，处理流程：

1. 解析命令行参数
2. 参数校验
3. 读取（或初始化）本地 JSON 数据文件
4. 追加新待办、分配 id、记录创建时间
5. 原子写回数据文件
6. 输出成功提示与待办 id

## 3. CLI 接口设计（AiWork 推荐）

命令形式：`todo add <名称> [-d | --desc <描述>]`

| 参数 | 必填 | 说明 |
|------|------|------|
| `<名称>`（位置参数） | 是 | 事项名称，去首尾空白后长度 1~128 字符 |
| `-d` / `--desc <描述>` | 否 | 事项描述，最长 1024 字符，缺省为空串 |

请求示例：

```bash
$ todo add "整理周报" -d "汇总本周迭代进展，周五前完成"
✓ 已创建待办 #1：整理周报
```

## 4. 数据模型与存储

### 4.1 数据实体 TodoItem

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int64 | 自增主键（现有最大 id + 1） |
| name | string | 事项名称 |
| description | string | 事项描述 |
| created_at | string | 创建时间，RFC3339 格式 |

### 4.2 存储

- 文件：本地 JSON 文件，默认 `./todo.json`，可用 `--file` 覆盖。
- 结构：顶层对象包裹 items 数组。

```json
{"items":[{"id":1,"name":"整理周报","description":"汇总本周迭代进展，周五前完成","created_at":"2026-10-27T16:00:00+08:00"}]}
```

- 写入：先写临时文件再原子 rename，避免写入中断损坏已有数据。

## 5. 错误处理

| 场景 | 行为 |
|------|------|
| 缺少名称 / 名称为空或超长 | 输出错误与用法提示，非 0 退出码 |
| 描述超长 | 参数校验失败提示 |
| 数据文件损坏 / 不可解析 | 报错并提示文件路径，不覆盖原文件 |
| 文件写入失败 | 报错，保留原数据文件 |

## 6. 测试方案

- 单元测试：JSON 序列化 / 反序列化、参数校验、id 分配逻辑。
- 集成测试：执行 `add` 后读取文件验证数据；连续新增验证 id 递增与多条目持久化。

## 7. 验收标准

- `todo add "名称" -d "描述"` 执行成功，返回唯一 id。
- 数据持久化到本地 JSON 文件，字段含 name / description / created_at。
- 无名称时给出明确错误提示并返回非 0 退出码。
