### Step 5 决策记录

| 决策项 | 决策结果 | 备选方案 | 决策原因 |
|--------|----------|----------|----------|
| 成功响应结构 | 直接返回业务对象，不包 result/msg/data | 统一包壳 | PRD 4.7 已给出响应示例；无项目既有约定，避免前端二次拆包 |
| 错误结构 | 400/404/500 用 `detail.code/detail.message`；422 用 FastAPI 默认结构 | 全部统一为自定义结构 | PRD 4.7 固定契约；422 保留字段级定位 |
| PATCH 出参 | 返回更新后工单对象（不含 logs） | 返回空或仅状态码 | 前端可即时更新状态标签，随后调 W03 刷新记录 |
| 处理说明 note | 仅"处理中"状态允许提交，写 handling 记录 | 任意状态可写 | 避免给已完成/已关闭工单追加处理记录，破坏历史只读语义（Q-06 仅约束是否必填） |
| solution 校验 | 仅允许随 status=已完成 提交 | 允许提前保存草稿 | 需求只要求完成时填写；提前写入会与"完成后只读展示"冲突 |
| 编号生成 | 服务层 S01，查当日最大号 +1，唯一约束兜底重试 1 次 | 独立序列表/全局自增 | PRD 5.2 指定按日流水；单机演示无需序列表 |
| 并发控制 | 条件更新（WHERE id AND status=读取时状态）+ 写事务 | version 字段/分布式锁 | 单机单实例，条件更新即可防止过期状态覆盖；version 属无依据扩展 |
| 幂等 | 不做服务端幂等键，依赖前端按钮禁用 | 增加幂等键 | 同一设备允许多次报修，服务端无法区分重复提交与再次报修；幂等键会改变契约 |
| 仓储实现 | 标准库 sqlite3 封装 Repository，参数绑定 | SQLAlchemy ORM | 零额外依赖、SQL 可控，便于说明索引与条件更新；ORM 对演示规模无收益 |
| 状态机 | 4 状态 + 3 条正向流转 + 2 类自环（仅分派/追加说明） | 增加"已受理"等中间状态 | PRD 4.6 明确 4 状态且不产生第五种状态 |
| 模块设计顺序 | 工单管理 → 工单统计 → 演示数据初始化与运行支撑 | 按页面顺序 | 依赖拓扑排序，被依赖模块先设计 |
