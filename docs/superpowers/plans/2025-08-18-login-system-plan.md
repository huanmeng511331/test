# 登录系统实施计划

## 1. 概述

### 1.1 背景
本项目当前是一个基础 Go 项目，需要引入用户登录认证能力，为后续业务功能提供身份识别与权限管控基础。

### 1.2 目标
实现一套安全、可靠的账号密码登录系统，覆盖登录入口、身份校验、登录态管理及退出登录等核心能力。

### 1.3 名词定义
- **Session**：服务端维护的用户登录会话，标识已登录状态。
- **JWT**：JSON Web Token，用于无状态登录态传递（如采用 JWT 方案）。
- **bcrypt**：密码哈希算法，用于安全存储用户密码。
- **HttpOnly Cookie**：浏览器无法通过 JavaScript 访问的 Cookie，降低 XSS 风险。

## 2. 角色与范围

### 2.1 目标用户
- 系统管理员：管理系统用户、查看登录日志。
- 普通用户：使用账号密码登录系统并访问授权功能。

### 2.2 本期包含范围
- 账号密码登录（含"记住我"）
- 登录态维持（Session / JWT）
- 退出登录
- 输入校验、失败次数限制
- 基础安全加固（密码哈希、防枚举、防暴力破解）

### 2.3 本期不包含范围（明确排除）
- 用户注册
- 找回密码
- SSO 单点登录
- 第三方登录（OAuth / 微信 / GitHub 等）
- 多因素认证（MFA）
- 扫码登录

---

## 3. 功能需求

### 3.1 登录入口
- Web 端提供登录页面 `/login`
- API 端点 `POST /api/v1/auth/login`

### 3.2 输入校验
- 用户名/邮箱：非空，长度 3-50 字符，支持邮箱格式
- 密码：非空，长度 8-128 字符
- 验证码（可选，失败次数触发）：4-6 位数字或字母

### 3.3 核心认证流程
1. 客户端提交用户名/密码（及验证码）
2. 服务端查询用户信息
3. 验证密码（bcrypt 比对）
4. 生成登录凭证（Session 或 JWT）
5. 返回登录结果，客户端存储凭证

### 3.4 登录态维持
- **Session 方案**：服务端 Redis 存储 Session，客户端持 Cookie（HttpOnly + Secure + SameSite=Strict）
- **"记住我"**：勾选后延长 Session / Token 有效期（如 7 天 vs 2 小时）
- 每次请求携带凭证，服务端校验有效性

### 3.5 退出登录
- 客户端调用 `POST /api/v1/auth/logout`
- 服务端销毁 Session / 加入 Token 黑名单
- 客户端清除本地凭证

## 4. 异常与边界场景

| 序号 | 场景 | 预期行为 |
|------|------|---------|
| 1 | 账号不存在 | 返回统一文案"账号或密码错误"，避免枚举 |
| 2 | 密码错误 | 返回统一文案"账号或密码错误"，记录失败次数 |
| 3 | 暴力破解锁定 | 连续失败 5 次锁定账号 30 分钟，或触发验证码 |
| 4 | 账号禁用/冻结 | 返回"账号已被禁用，请联系管理员" |
| 5 | 登录态过期/无效 | 返回 401，要求重新登录 |
| 6 | 并发登录超限 | 可选：限制同一账号同时在线数（如 3 个） |
| 7 | IP 限流 | 单 IP 10 分钟内超过 20 次登录请求触发限流 |

---

## 5. 非功能需求

### 5.1 安全
- 密码使用 bcrypt（或 Argon2）加盐哈希存储，cost ≥ 10
- 账号不存在与密码错误统一返回"账号或密码错误"
- 失败次数限制 + 验证码 + IP 限流 防暴力破解
- Cookie 设置 HttpOnly + Secure + SameSite=Strict
- 传输层启用 HTTPS
- 敏感操作记录审计日志

### 5.2 性能
- 登录接口响应时间 P99 < 500ms
- 登录校验支持异步写日志，不阻塞主流程
- Redis Session 查询 P99 < 10ms

### 5.3 可用性
- 登录服务可用性 ≥ 99.9%
- 降级方案：验证码服务不可用时允许基础登录（视策略）

### 5.4 兼容性
- 支持主流浏览器（Chrome / Firefox / Safari / Edge）最新两个主版本
- API 兼容 RESTful 规范，返回 JSON 格式

## 6. 接口示例

### 6.1 登录接口

**请求：**
```
POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "user@example.com",
  "password": "SecureP@ssw0rd",
  "remember_me": true,
  "captcha": "123456"  // 可选，触发时必填
}
```

**成功响应：**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "expires_at": "2025-08-18T14:00:00Z",
    "user": {
      "id": "u_123456",
      "username": "user@example.com",
      "display_name": "张三"
    }
  }
}
```

**失败响应：**
```json
{
  "code": 10001,
  "message": "账号或密码错误"
}
```

### 6.2 退出登录接口

**请求：**
```
POST /api/v1/auth/logout
Authorization: Bearer <token>
```

**响应：**
```json
{
  "code": 0,
  "message": "success"
}
```

## 7. 验收标准

| 序号 | 验收项 | 验收方式 |
|------|--------|---------|
| 1 | 正确账号密码登录成功，返回有效 Token / Session | 接口测试 |
| 2 | 错误密码返回"账号或密码错误"，不泄露账号是否存在 | 接口测试 |
| 3 | 连续失败 5 次触发锁定/验证码 | 接口测试 + 自动化测试 |
| 4 | 登录态过期后访问受保护接口返回 401 | 接口测试 |
| 5 | 退出登录后 Token / Session 失效 | 接口测试 |
| 6 | "记住我" Token 有效期大于普通登录 | 接口测试 |
| 7 | 密码在数据库中以 bcrypt 哈希形式存储，不可反解 | 代码审查 + 数据库检查 |
| 8 | 登录接口单接口 QPS 压测满足 ≥ 1000 req/s | 性能压测 |

## 8. 后续规划

- **第三方登录**：支持微信、GitHub、Google OAuth 2.0 登录
- **扫码登录**：移动端扫码 PC 端登录
- **MFA 多因素认证**：短信验证码、TOTP（Google Authenticator）
- **SSO 单点登录**：企业内部统一身份认证
- **登录日志审计**：可视化登录历史、异常登录告警
- **密码策略增强**：定期强制修改密码、历史密码校验

## 10. 风险与依赖

| 风险 | 缓解措施 |
|------|---------|
| bcrypt 计算耗时长影响性能 | 异步处理、调整 cost 参数、压测调优 |
| Redis 故障导致 Session 不可用 | 引入降级方案（如本地缓存 + 数据库备份） |
| 暴力破解攻击 | 失败次数限制 + 验证码 + IP 限流多层防护 |
